# orchestrate-tasks.ps1: sequential task queue on a queue branch

`scripts/orchestrate-tasks.ps1` runs the autonomous tracker tasks of one repository one at a time, each in a fresh headless agent process (Claude Code, Codex or Gemini CLI through `SecondBrain.AgentAdapters`), and commits locally after each. It is independent of `run-ready-tasks.ps1`: use it when the tasks themselves change the runner.

- Entry point (`scripts/queue.ps1`, chat `sb queue`, `sb queue status`, `sb queue stop`): run it from any managed repository; no option, a preview; `-Start` starts a detached `-Run`; `-Provider`, `-Model`, `-Effort`, `-MaxTasks`, `-OnlyIds`, `-ExcludeIds`, `-Branch`, `-TrackerPath` and `-AllowNoPowerRequest` are forwarded, everything else (`-ConfirmExtendedTools`, `-HealthChecks`, ...) needs a direct call. The dossier is found through the Git `origin` identity (a repository without a GitHub origin needs `-TrackerPath`), and the first preview of a repository should show at least one selected task before `-Start`.
- `-Candidates` (chat `sb queue -Candidates`): read-only JSON of the open tasks the queue cannot take yet, by priority, each with its `reasons` (`execution:`, `awaiting:`, `stream:`, `dependencies:`, `readiness:<check>:<missing>`) and the missing `advisory` files and checks; `-NeedsOwner` drops the tasks that only wait for dependencies, `-IncludeAdvisory` adds tasks that only lack files or checks, `-Limit N` returns the first N, `-OnlyIds` and `-ExcludeIds` narrow it. It feeds the card with role `tasks.prepare` (workflow `wf-prepare-unattended`): ask how many tasks to prepare, make each candidate self-sufficient one at a time with the owner, register it, preview, then start `sb queue -Start` or the runner on the owner's go-ahead.
- Finds the checkout (Git root of the current directory), SecondBrain (`SECONDBRAIN_HOME`, else the folder above the script) and the dossier (Git `origin` identity in `repository.json` under `repos`); creates its work folder with `work.ps1` (`.runtime/hosts/<host>/repos/<repo>/report/<date>-task-run`).
- Preview by default. `-Run` creates a `queue/<yyyyMMdd-HHmm>` branch (or `-Branch`; never `master` or `main`; skipped when already on a `queue/*` branch), then starts a pinned copy of the script. No push, ever.
- `-Provider claude|codex|gemini` (default `claude`), `-Model`, `-Effort`, `-AgentPath`, `-TimeoutMinutes` per task (default 45), `-MaxTasks`, and `-OnlyIds` / `-ExcludeIds` to narrow the selection. Tool access of the task sessions: `-PermissionMode acceptEdits`, an explicit `-AllowedTools` list and a `-DisallowedTools` list (git commit, push, tag, reset, clean, rebase, `rm`, `Remove-Item`). Changing any of the three needs `-ConfirmExtendedTools` (Claude Code only); the profile, the confirmation and the time are recorded in `status.json`.
- Per task: clean tree required (except the interrupted task on resume), task marked `in_progress`, session run, a `done` without evidence reopened, a task that ends without a result parked as `user_required`, a local commit of the changed paths (the rollback point), run evidence offered to the tracker, then the health check: tracker readable, `knowledge.ps1 -Tasks`, `test-secondbrain.ps1 -Quick`, `secondbrain.ps1 -Check` (`-HealthChecks` selects a subset). A failed check stops the run with a `NOTICE.txt`; nothing is reverted, reset, cleaned or stashed.
- Bookkeeping target (#773): a linked Git worktree has no binding of its own and inherits the binding of the checkout that shares its Git directory, only when its origin is the one that binding was activated with; several candidates are ambiguous, a changed origin or an unrelated clone gains nothing. Before any agent starts, the preflight checks that the checkout resolves (as `knowledge.ps1` does) to the identity of the dossier the queue reads and that `knowledge.ps1 -Tasks` works; otherwise the run stops with a notice, exit 1 and no session. A start, status or evidence write counts only when the tracker reports it `applied`; a rejection is a `bookkeeping-rejected` event, never logged as done or parked, and stops the run. `status.json` ends with `result` (`completed` or `failed`) and `exitCode`; a fatal bookkeeping or health error exits nonzero.
- Worker report: with `-WorkerReport` (default for `-Provider codex` and `gemini`) the sandboxed worker does not touch the dossier, the tracker or the workstation configuration (its sandbox is unchanged); it ends its answer with one `SB-RESULT: {"taskId":…,"status":"done|todo|blocked","evidence":[{"reference":…,"outcome":…}],"reason":…}` line. The host accepts it only for the running task, with at most 10 relative evidence references and the tracker outcomes (`passed`, `failed`, `partial`, `unverified`), and records the evidence and the transition (`done` needs a `passed` entry; `blocked` parks the task as `user_required`) from the checkout through `knowledge.ps1`. A missing or invalid line is handled as a session that ended without an outcome.
- Selection: autonomous, `todo` or `in_progress`, dependencies done, not in the excluded streams of the runner, not waiting for a person, not screen-bound (`-ExcludePattern`, lifted by `-IncludeExcluded`). Tasks that edit the orchestrator or the runner themselves (`-SelfPattern`) are ordered last.
- Readiness (#744): the stored `extensions.readiness` is honoured. A task with a failed check (objective, inputs, acceptance, dependencies, tools or decisions) is skipped with a `skip` event and the reason `readiness:<check>:<missing>`; the legacy scope check that lacks only a stream, and the authorization check (decided by the execution filter), do not block. `extensions.files` and `extensions.checks`, when present, are listed in the task prompt as the files in scope and the checks to run before closing. `run-ready-tasks.ps1` applies the same rule and lists the same lines.
- The quota is read before every task (`Get-SBAgentQuota`: Codex session files, else the last observation an agent reported) and recorded as a `quota-check` event and in `status.json`. An exhausted quota, or a current window used at `-QuotaLowPercent` (default 95) or more, waits for its reset; a reset beyond `-MaxWaitHours` stops the run with a notice before the task starts. A provider without a quota source is `unknown` and never fails or blocks the run. Quota limits hit during a session also wait for the reset (`-MaxWaitHours`) and retry; three consecutive failures stop the run. On Windows the run holds a system-required power request (no idle sleep); if it is refused the run does not start unless `-AllowNoPowerRequest`.
- `-TrackerPath <tracker.json>` names the tracker of the dossier explicitly; without it the script resolves the dossier from the checkout's Git `origin` identity. A pinned `-Run` forwards it to the copy it starts.
- `-Status` prints the latest run (phase, pid alive, interrupted, current task, counters, notice, last events). Phases: `starting`, `running`, `waiting-quota` (the run waits for a quota reset, `waitingUntil` says when; do not restart it), `finished`. A run whose pid is gone while the phase is `starting`, `running` or `waiting-quota` is reported as interrupted. `-Stop` creates `stop.flag` so the run ends before the next task. Both fail with `No orchestrator run found for <checkout>` (exit 1) when no run exists yet. Without an activated workstation the script stops with `Workstation not activated`; run `scripts/secondbrain.ps1 -Setup` first.
- Resume: a run cut while `running` (pid gone) is resumed by running `-Run` again. The work folder and counters come from `status.json`; the interrupted task goes first, its dirty tree is accepted for that task only, and its prompt says to continue the partial work.
- `-InstallAgent -Provider claude|codex|gemini` writes a context-free supervisor agent definition into the checkout and never overwrites an existing file. Only the Claude Code format (`.claude/agents/task-queue-supervisor.md`) is verified; the Codex and Gemini files are plain definitions to adapt.
- Limits: `-Run` copies `scripts/`, `config/` and `VERSION` into `snapshot-<time>/` in the work folder (#665); the pinned run takes its modules, `knowledge.ps1` bookkeeping and the `-Quick` and `-Check` health checks from that copy while `SECONDBRAIN_BRAIN_ROOT` points it at the live dossier (the variable must name a SecondBrain checkout, otherwise the scripts refuse to start). A task that edits a script therefore cannot break the run's own bookkeeping; the SHA-256 manifest (scripts, `config/` and `VERSION`) reports `scripts-changed` after each task, and when a task changed any of them the run retakes the snapshot between tasks (event `snapshot` with the new manifest hash), so the next health checks and bookkeeping use the current code; a snapshot is never modified while a task runs. A run resumed without a snapshot uses the live scripts. The health check compares `-Quick` and `-Check` with their exit codes at the start of the run, so a repository that already fails one of them is not stopped by it. Extended tool access works with Claude Code only. `-InstallAgent` and `-Run` write (the agent file, the branch); a bare call or `-Status` only reads.

## Planned, not implemented: full permissions for the runner

`run-ready-tasks.ps1` starts agents with a fixed permission profile: file edits in the checkout, no Git history changes, no deletion, and it has no parameter to change it. `orchestrate-tasks.ps1` already exposes the profile (see the third bullet above); the same setting is planned for `run-ready-tasks.ps1` and the orchestrator app:

- Add a runner setting (per run, in the orchestrator app and as a `run-ready-tasks.ps1` parameter) that selects the permission profile: standard (today) or extended (as in chat).
- Require an explicit confirmation before the run for the extended profile, and record the profile, who confirmed and when in `status.json` and the run report.
- For `orchestrate-tasks.ps1`, widen `-PermissionMode`, `-AllowedTools` and `-DisallowedTools` only with the user's prior authorization.
- Keep the forbidden actions of the repository directives (commit, push, publication, deletion) outside the extended profile unless the authorization names them.
