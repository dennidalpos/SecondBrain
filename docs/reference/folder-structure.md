# Folder structure and write permissions

Reference guide: what lives where, who can write, and where. Valid from the directive revision of 10 November 2026.

## Top-level folders

| Folder | Role | Who writes | Git |
|---|---|---|---|
| `repos/<repo>/` | One dossier per managed repository: context, memory, tracker, specs, history | Only SecondBrain scripts and the MCP write tools | ignored |
| `workstation/<id>/` | Ongoing responsibilities with no end: `governance`, `postazione`, `directives` | Scripts and the owner | ignored |
| `shared/<id>/` | Shared references: authoritative sources, architecture, technology radar, troubleshooting | Scripts and the owner | tracked, except downloadable originals |
| `config/` | Shared schemas and policies, no local data | Manual review | tracked |
| `directives/` | Source texts of directives, prompts, proposals | Manual review; changes go through `approve-revision.ps1` | tracked |
| `docs/`, `scripts/`, `.github/` | Guides, code, automation | Manual review | tracked |
| `.runtime/` | State and work generated by the workstation, never knowledge | Only scripts | ignored |

Of `repos/` and `workstation/`, only the folder's `README.md` is tracked; `shared/` is tracked. There are no archive folders: an inactive entity has a status other than `active` and keeps its place.

Creating entities: `entity.ps1 -NewProject`, `-NewArea`, `-NewResource`; status change `-SetStatus`; closing `-Archive` (status only).

## Repository dossier (`repos/<repo>/`)

| File or folder | Role |
|---|---|
| `brief.md` | Purpose and scope (required by `secondbrain.ps1 -Check`) |
| `context.md` | Current state, constraints, open problems, next step |
| `memory.md`, `memory.agent.md` | Durable decisions; the second is the generated agent view |
| `tracker.json` | Active tasks (schema 1) |
| `repository.json`, `entity.json`, `index.md` | Identity, entity type and status, generated index |
| `authoritative-sources.json` | The repository's authoritative sources |
| `specs/` | Repository specifications |
| `history/` | Reports, compactions, finished tasks; not published |

## `.runtime`

```
.runtime/
  access/                      sessions, locks and the write queue
  hosts/<host-id>/             workstation state
    *.json, global instructions file   configuration, selection, inventory, IDE map, state
    backups/para-*/            backups and markers of dossier write transactions
    repos/<repo>/<category>/<yyyyMMdd>-<slug>/   work with MANIFEST.json
                               categories: work, evidence, report, fixture, tmp
    repos/tests-<hash>/        test-suite fixtures, can be emptied
```

Rules:
- Create work folders only with `work.ps1 -Init`; never create files or folders by hand in the `.runtime` root.
- `access.ps1 -Start` opens a write session: it accepts a new `-SessionId` (32 hexadecimal digits) or generates one and returns it. Pass the same value to every CLI and to `-End`. Closed or expired sessions are removed on every `-Start`.
- `.runtime` can be deleted and recreated with a new Setup (`secondbrain.ps1 -Setup -Roots <folders>`): it holds only regenerable state.

## Where an agent writes

| Agent | Can write | Cannot write |
|---|---|---|
| Session in a product repository | The repository itself; in SecondBrain only `repos/<repo>/` (through scripts or MCP) and `work.ps1` folders | Other dossiers, `workstation`, `shared`, `.runtime` by hand |
| Session in SecondBrain | `directives/`, `scripts/`, `docs/`, `config/` and PARA through scripts | `.runtime` by hand |
| Task runner | Only its own repository's dossier | Any other path |

A path outside these rules is reported to the owner and not written.
